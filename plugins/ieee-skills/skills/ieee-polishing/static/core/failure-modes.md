# Common IEEE Writing Failure Modes

## Section-level failures

| Section | Common failure | Fix |
|---|---|---|
| Abstract | Too vague, no numbers | Add key quantitative results |
| Introduction | No clear gap statement | State what prior work failed to solve |
| Method | Missing parameter values | Add all hyperparameters, settings |
| Results | Narrative without data | Lead with numbers, then explain |
| Discussion | Overclaiming | Match claims to evidence strength |
| Conclusion | Repeating abstract | Summarize contributions, not findings |

## Sentence-level failures

1. **Hedging overload** — "may possibly suggest", "could potentially indicate" → Use direct statements when supported by evidence.
2. **Citation clutter** — "[1], [2], [3], [4], [5]" after every sentence → Cite only the most relevant 1-2 references per claim.
3. **Meaningless intensifiers** — "very", "extremely", "highly" → Replace with numbers.
4. **Redundant phrases** — "It is worth noting that", "It should be pointed out that" → Delete.
5. **Ambiguous pronouns** — "This shows..." → "This result shows..."

## Structural failures

1. **Paragraph lacks topic sentence** — State the point in the first sentence.
2. **Single-sentence paragraph** — Merge or expand.
3. **Wall of text** — Break paragraphs longer than 8-10 sentences.
4. **No transition** — Connect paragraphs with logical bridges.
